# Secure Slots — защищённая версия Web Security Testbed

Игра на виртуальные токены с регистрацией, ролями и админ-панелью. Вся логика и проверки прав
перенесены на сервер. **Внешних зависимостей нет** — только встроенные модули Node.js (≥ 18),
поэтому нечего обновлять из-за чужих уязвимостей и нечем заразить цепочку поставок.

## Запуск

```bash
# разработка
ADMIN_PASSWORD='придумайте-длинный-пароль' node server.js
# откройте http://127.0.0.1:3000

# тесты безопасности (26 проверок, ~10 секунд)
npm test
```

Админ-аккаунт создаётся при старте из переменных окружения (по умолчанию имя `admin`, меняется через
`ADMIN_USER`). Если `ADMIN_PASSWORD` не задан, администратора нет вообще. Пароль — от 12 символов.
Роль `admin` нельзя получить через регистрацию или запрос с сайта.

## Что было не так в исходном коде и как исправлено

| Было (клиентский код) | Стало |
|---|---|
| Сессия — объект в JS: в консоли `activeSession.role = "admin"` открывало админ-панель | Сессия хранится на сервере; браузер получает случайный идентификатор в cookie `HttpOnly` + `SameSite=Strict` |
| Вход без пароля, любое имя | Пароли (от 10 символов) хранятся как `scrypt`-хэш с солью, сравнение за постоянное время |
| Баланс — переменная в браузере (`accountTokens = 999999`) | Баланс только на сервере; клиент лишь показывает ответ |
| Результат игры — `Math.random()` в браузере | Результат определяет сервер через `crypto.randomInt` |
| Админ-функции проверяли роль на клиенте | Каждый админ-запрос проверяет роль по серверной записи + CSRF-токен; действия пишутся в аудит-лог |
| IDOR / BOLA: чужие данные доступны по идентификатору | Идентификатор пользователя нигде не принимается от клиента (кроме админа, и там он валидируется) |
| Inline-скрипты и стили | Строгий CSP без `unsafe-inline`; код вынесен в `app.js` и `style.css`; вывод только через `textContent` |
| Нет защиты от перебора | Блокировка аккаунта после 5 ошибок на 15 минут, лимит попыток входа на IP, лимит запросов к API |
| Двойное списание при параллельных запросах | Проверка баланса и списание — один синхронный шаг; плюс серверный «cooldown» между спинами |

Дополнительно: ротация сессии при входе (защита от session fixation), хэш идентификатора сессии
в памяти, лимит сессий на пользователя, таймауты бездействия (30 мин) и жизни (8 ч), проверка
`Origin` / `Sec-Fetch-Site`, требование `application/json`, лимит размера тела (2 КБ), единый ответ
для «нет такого пользователя» и «неверный пароль», запрет имён-«двойников» (только ASCII),
общие сообщения об ошибках без стектрейсов, заголовки `X-Content-Type-Options`, `X-Frame-Options`,
`Referrer-Policy`, `Permissions-Policy`, COOP/CORP, HSTS в production. Статика отдаётся из
белого списка файлов в памяти, поэтому обход каталогов (`../`) невозможен.

## Переменные окружения

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `PORT` | `3000` | Порт |
| `HOST` | `127.0.0.1` | Адрес прослушивания (в контейнере — `0.0.0.0`) |
| `NODE_ENV` | — | `production` включает `Secure`-cookie (`__Host-sid`), HSTS, `upgrade-insecure-requests` |
| `ADMIN_USER` / `ADMIN_PASSWORD` | `admin` / нет | Администратор (пароль от 12 символов) |
| `TRUST_PROXY_HOPS` | `0` | Сколько прокси стоит перед сервером (для корректного IP в лимитах) |
| `ALLOWED_HOSTS` | пусто | Разрешённые `Host`, через запятую, например `slots.example.com` |
| `DATA_DIR` | `./data` | Где лежат `users.json` и `audit.log` (права `0600`) |
| `MAX_USERS` | `10000` | Потолок регистраций |
| `SPIN_COOLDOWN_MS` | `1500` | Пауза между спинами |
| `AUTH_RATE_MAX` / `API_RATE_PER_MIN` | `15` / `120` | Лимиты на IP |

## Перед выкладкой в интернет

1. **HTTPS обязателен.** Поставьте перед сервером nginx/Caddy с сертификатом, запускайте с
   `NODE_ENV=production`, `TRUST_PROXY_HOPS=1`, `ALLOWED_HOSTS=ваш.домен`. Без HTTPS cookie
   с флагом `Secure` работать не будет, а пароли пойдут открытым текстом.
2. Делайте резервные копии каталога `data/` и не отдавайте его через веб-сервер.
3. Запускайте под отдельным пользователем без прав root, через systemd/Docker с автоперезапуском.
4. Следите за обновлениями Node.js (LTS).

## Честные ограничения

- Сессии лежат в памяти: после перезапуска сервера все входят заново, и работает только один экземпляр.
  Для нескольких экземпляров нужны общее хранилище сессий (Redis) и база данных вместо `users.json`.
- Нет восстановления пароля, подтверждения почты и 2FA.
- Блокировка по аккаунту защищает от перебора, но позволяет злоумышленнику временно заблокировать
  чужое имя (компромисс; лимит по IP это смягчает).
- Если планируете **реальные деньги**, этого недостаточно: нужны лицензия, KYC, ответственная игра
  и независимый аудит. Проект рассчитан на виртуальные токены.

## Заметка об игре

Шанс трёх одинаковых цифр из 7 равен 1/49. При выплате 500 за ставку 10 математическое ожидание
выигрыша ≈ 10,2 токена за спин, то есть игра слегка в пользу игрока (≈ 102 %), как и в исходном коде.
Если нужен «дом в плюсе», уменьшите `jackpotPayout` в `server.js` (например, 400 → ≈ 82 %).
